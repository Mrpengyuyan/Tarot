# Phase 75 — 抽牌的真实性

用户体验 Phase 74 后提出三点：洗牌再慢一秒；选牌时 78 张已经全部摊开，左上角不该还留着牌堆；抽到的牌必须不重复，并且有正位也有逆位。逆位概率由用户选定为 50%，前后端一起改。

## 1. 洗牌加长到约 4 秒

在 Phase 74 的 3 秒节奏上，每一段都再延长三分之一：按压 0.25 秒、切牌 0.72 秒、再切 0.52 秒，每张落牌 0.26 秒，交错间隔 0.088 秒，方齐回弹 0.22 秒，停留 0.55 秒，总计约 4.0 秒。由 `Phase75DrawTruthBootstrapper` 写入场景。

## 2. 选牌时牌堆消失

扇面就是整副 78 张牌，所以桌上不该再有牌堆。`SpreadFanController` 在摊牌时让牌堆从上往下一层层消失，与牌离开牌堆的进度同步，扇面摊完时牌堆正好没了；收拢时再一层层长回来。中途出错放弃扇面时（`Abandon`），牌堆立即恢复。只切换摊牌开始时原本就显示的渲染器，其他状态不动。

## 3. 抽牌不重复，有正位也有逆位

**原来的离线抽牌**（`LocalReadingSimulator.CreatePlaceholderDraws`）不是抽牌：永远是「愚者、魔术师、女祭司……」按固定顺序排下来，一共只有 12 张大阿卡纳，而且每第三张固定是逆位。它现在只作为测试夹具保留，很多旧测试依赖它的固定内容。

**现在的离线抽牌**（`LocalReadingSimulator.DrawFromDeck`）：
- 牌库是完整的 78 张，数据来自后端的种子文件 `Server/data/tarotCards.json`，由批处理脚本复制成 `Assets/Resources/TarotDeck/tarot_cards.json`（只保留离线需要的字段：编号、中英文名、序号、大小阿卡纳、花色、正位含义、逆位含义、关键词），通过 `TarotDeck` 读取。测试会逐张比对两份数据，后端的牌库一改，测试就会失败，提醒重新运行批处理脚本。
- 用 Fisher–Yates 洗整副牌，从顶上发出所需张数，所以同一次抽牌里不会出现重复的牌。
- 每张牌以 50% 的概率为逆位，含义和关键词取对应朝向的那一份。
- 抽不出时（牌库数据缺失）退回占位牌。

**后端**：原来就是从 78 张里不放回地抽，天然不重复；逆位概率原为 30%，现在改为 50%。实现提成常量 `REVERSED_PROBABILITY` 和函数 `draw_orientations`，新增 `tests/test_draw_orientation.py`。Unity 端有测试读取这个常量，保证前后端概率一致。

**逆位牌在桌上倒着放**：翻开后，逆位牌的图案旋转 180°（`CardView` 按 `is_reversed` 旋转牌面图案），和结果页的逆位显示一致。

## 测试

- EditMode `Phase75DrawTruthTests`：
  - 洗牌约 4 秒；
  - Unity 的牌库与后端逐张一致；
  - 逆位概率与后端常量相同且为 0.5；
  - 300 次十张牌的抽取中从不重复，并且 78 张都抽到过；
  - 4000 张里逆位约占一半，含义与朝向一致；
  - 同一个随机种子得到相同结果，牌位名称正确；
  - 78 张每张都能找到牌面图；
  - 逆位牌的图案倒置，重新绑定为正位后转回来；
  - 本文档存在。
- PlayMode `Phase75DrawTruthPlayTests`：
  - 选牌时桌上的牌堆全部隐藏，收拢后全部恢复；
  - 离线一局发出的牌都来自真实牌库、含义对应朝向、没有重复，桌上的牌就是这些牌。
- 后端 `tests/test_draw_orientation.py`：逆位概率 0.5，4000 次中约一半为逆位，结果随种子确定。
- `Phase72ShuffleTests` 的时长范围改为 3.7–4.4 秒；`Phase74DrawFeelTests` 的时长检查改为「不少于 3 秒」。
