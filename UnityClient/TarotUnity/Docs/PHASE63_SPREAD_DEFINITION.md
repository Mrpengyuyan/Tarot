# Phase 63 — SpreadDefinition Data Model + Celtic Cross

Adding a spread used to mean editing the same "1 vs 3" branch in four places
(table layout, socket glows, camera framing, offline reader). Phase 63 makes a
spread **data**, then adds the ten-card **Celtic Cross** on top of it.

## The data model

- `SpreadDefinition` (ScriptableObject): a spread's id, card count, display name,
  table slot placements (in reading order), position names + meanings, and camera
  framing (position / euler / fov).
- `SpreadCatalog` (ScriptableObject, in `Resources/Spreads/`): the list of spreads,
  with `GetById` / `GetByCardCount`. It is the single source of truth.

Assets generated: `SpreadDefinition_OneCard`, `_ThreeCard`, `_CelticCross`, and
`SpreadCatalog` — all under `Assets/Resources/Spreads/`. They are regenerated by the
Phase 63 bootstrapper and can also be hand-edited.

## Systems now read the catalog (no more 1/3 switches)

Everything keys off **card count**, so distinct-count spreads register cleanly:

- `SpreadLayoutController` — a list of slot sets by card count (`ConfigureSpread`);
  `GetSlots(count)` returns that spread's table slots.
- `CameraChoreographyController` — a `spreadPoses` list by card count; `FocusSpread`
  uses the registered pose (Celtic gets a pulled-back shot), falling back to the
  legacy one/three-card poses.
- `RitualStepIndicator` — socket glows are `SpreadGlowSet`s by card count, so the
  drawn spread lights its own sockets.
- `ReadingRoomController` — a "凯尔特十字" button selects the ten-card spread, and the
  offline draws take their position names/meanings from the definition.
- `LocalReadingSimulator` — `CreatePlaceholderDraws` accepts position names/meanings
  and carries twelve distinct placeholder cards so a Celtic reading has no repeats.

## The Celtic Cross

Ten cards: a six-card cross (现状 / 挑战 / 根基 / 过去 / 顶冠 / 未来, laid out
non-overlapping so each is clickable) plus a four-card staff (自我 / 环境 / 希望与恐惧
/ 结果). The Phase 63 bootstrapper builds ten table slots, ten recessed sockets
(`MP_CelticSockets`), ten warm glow quads (`MP_CelticSocketGlows`) and a camera pose
(`MP_CelticCrossPose`) from the definition, then wires them by count. The one- and
three-card spreads keep their existing scene objects untouched.

The result screen needs no change — Phase 62's dynamic row lays out all ten cards and
takes their labels from the draws' position names.

Slot coordinates and the camera pose are a first pass, tuned from the review capture.
